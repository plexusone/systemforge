# v0.31.0

**Release Date:** 2026-11-04

A security release that keeps one admin account from taking over an
organization:

- **Owners manage admins.** An admin manages members and collaborators.
  Granting the admin role, changing, deactivating or removing another admin,
  changing another admin's application roles, and sending, resending or
  revoking admin invitations now need an owner, as owner changes already did.
  An admin may still step down or leave. A pending admin invitation sent by an
  admin can no longer be accepted, and demoting an owner revokes the admin
  invitations it sent. A member change applies only while the member still
  has the role it was authorized against, so a promotion landing at the same
  moment cannot be overwritten; a changed membership answers 409.
- **Return addresses stay on their host.** A `return_to` path such as
  `/.//evil.example/x` starts with a single slash, but resolves to
  `//evil.example/x`, another host, in a client that rebuilds the URL from its
  path. Sign-in's redirect policy, `Server.ValidateReturnTo` and the
  relying-party BFF now refuse paths with dot segments, plain or
  percent-encoded.
- **New URLs are https.** Organization logo and website URLs and
  application logos must be absolute https URLs, with a host name, when they
  are written. Avatars from identity providers that are not https are not
  stored, so sign-in never fails over one. URLs already stored are not
  changed.

The release is breaking: admins who managed other admins are now refused,
URLs that are not https are refused on write, and `organization.Service`
gains `RemoveMemberIfRole`. Read
[Upgrading](#upgrading) first.

## Upgrading

- Have an owner revoke any pending admin invitation an admin sent, then
  create a new one. It can no longer be accepted; resending keeps its
  original inviter, and a pending invitation blocks a new one for the same
  email.
- Make everyone who should manage admins an owner. Keep at least two owners
  per organization: otherwise only a platform administrator can change the
  admins of an organization whose only owner is unavailable.
- Existing stored URLs are not changed and are still served. Replace or
  clear organization logo and website URLs, application logos and people's
  avatar URLs that are not https. A write is refused only when it supplies a
  URL that is not https.
- Implementations of `organization.Service` outside SystemForge must add
  `RemoveMemberIfRole`.
- Clients that send `return_to` with dot segments must send the canonical
  path.

See [Member endpoints](../design/architecture/organizations.md#member-endpoints)
and the [invites guide](../guides/invites.md#permissions).
