# v0.14.0

**Release Date:** 2026-10-09

A breaking release with three themes. **Principal is the sole identity
root**: the legacy User model and its tables are gone, so password login,
social login, federation sync, and SCIM all resolve a person to the same
principal (ADR-004). **Managed principals** let an application create humans
without an email, such as young learners, whom guardian and educator
managers control and sign in with QR-friendly login tokens (ADR-005). And a
**security pass** makes the marketplace, organization, and invite APIs act
for the authenticated caller and check organization permissions, instead of
trusting the IDs a request names. Read the upgrade notes before deploying.

## Highlights

- **One identity model** — `Principal(type=human)` + `Human` everywhere; `systemauth.Storage` works on `HumanPrincipal`.
- **Managed principals** — opt-in per deployment and per client; `guardian` and `educator` managers; login tokens, a rate-limited exchange endpoint, manager visibility and revocation, guardian claims, and attaching an email later. See [Managed Principals](../identity/managed-principals.md).
- **Caller-bound, authorized APIs** — the marketplace, organization, and invite APIs identify the caller through `requestprincipal` and check organization permissions; without an authorizer they refuse rather than trust the request.
- **Provider parity** — the simple and SpiceDB providers grant identical organization and manager permissions, enforced by a parity test against the base schema and a shared conformance suite.
- **AI agents at resource servers** — `identity/requestprincipal` with an AAuth authenticator (`aauthrs`) next to bearer, API-key, and BFF-session authentication.

## Security

These fix vulnerabilities present in v0.13.0. Upgrade promptly.

- Marketplace checkout took the purchaser from the request body, so anyone could start a purchase in another principal's name for any organization.
- Marketplace listing, license, and seat endpoints acted on any IDs a request named.
- The organization API listed every organization and let any caller read, change, or delete organizations, change members, and transfer ownership.
- Invite management needed no permission, and anyone holding an invite link could accept it as any principal.
- Invite tokens were stored in plain text; they are now SHA-256 hashes.
- SpiceDB principal and organization cleanup ignored failures and missed editor and manager relations, leaving access behind while reporting success.
- Refresh tokens could be used more than once, and refreshing near expiry extended a session indefinitely; rotation is now atomic, a session keeps its original expiry, and reusing a rotated refresh token revokes the whole token family.
- Stripe checkout granted a license before a delayed payment cleared, an invalid seat count produced an unlimited seat-based license, and cancelling a subscription left its license in place.
- Deactivating a principal did not stop its tokens: access tokens stayed valid and refresh tokens kept issuing new ones for up to 30 days. Tokens of an inactive principal are now refused wherever they are used or refreshed.
- Agent delegation failed open: revoking a delegation gave the agent unrestricted access, constraints that did not overlap allowed everything, and expiry and action limits were never stored.
- Revoking platform administration through `principal.UpdateHuman` was not synced to SpiceDB.
- Signing up with an invite accepted any email, and `SignupOrGetExisting` returned existing accounts for unverified emails.
- Anyone who could reach SystemAuth's authorization endpoint, or `identity/oauth`'s, could obtain tokens for any user by sending an `X-User-ID` header. Header identity is now an explicit, gated opt-in, and `identity/oauth` also requires consent for third-party clients.
- Rate limits, BFF sessions, and API key usage records believed client-supplied `X-Forwarded-For`, `X-Real-IP`, and Cloudflare headers, so a client could evade a limit or forge its address. They now key on the direct peer and believe forwarding headers only from proxies you configure.
- SCIM listings skipped authorization, and a SCIM API mounted without a hook was open; the federation identity sync endpoint trusted its request body from anyone; token introspection accepted any token or public client as the caller; and the default storage accepted replayed client assertions.
- API keys could be managed by ID alone and granted any scope when no allow-list was set; the BFF proxy could forward the browser's session cookie upstream; concurrent logins could exceed the lockout limit; and `multiapp` trusted the `X-App-ID` header.
- BFF cookies could lose `Secure` and `HttpOnly`; cookie-authenticated writes skipped the same-origin check; JWTs without `exp` were accepted; client secret checks revealed which client IDs exist; and `multiapp` could leave one application's schema on a pooled connection.

## Upgrade Notes

### 1. Database

Run these against an existing PostgreSQL database; a fresh database needs
only `systemauth migrate`.

| Script | When | What |
|--------|------|------|
| `migrations/0002_drop_legacy_user_tables.sql` | **Before** starting v0.14.0 | Creates the system service principal, reassigns OAuth apps owned by legacy users, drops the legacy tables |
| `migrations/0003_hash_invite_tokens.sql` | When deploying v0.14.0 | Hashes stored invite tokens so outstanding invite links keep working |

Both are safe to run more than once. Then run `systemauth migrate` (or
`systemauthsvc.Service.Migrate`) for the new tables and columns:
`sf_manager_relationships`, `sf_manager_claims`, `sf_client_assertion_jtis`,
the `login_token` credential type, and `OAuthApp.managed_principals_enabled`
and `login_token_ttl`.

### 2. Configure authorization for the HTTP APIs

The marketplace, organization, and invite APIs now require an
authenticated caller, set by `requestprincipal.Middleware`, and an
authorizer. Until the authorizer is configured, organization-scoped
endpoints answer `501`.

```go
orgs := organization.NewService(db)
authorizer := rbac.New(
    rbac.WithRoleGetter(organization.MembershipRoleGetter(orgs)),
    rbac.WithPlatformAdminChecker(isPlatformAdmin), // optional
)

orgCfg := organization.DefaultAPIConfig()
orgCfg.Authorizer = authorizer
orgAPI := organization.NewAPI(orgs, orgCfg)

inviteCfg := invite.DefaultAPIConfig()
inviteCfg.Authorizer = authorizer
inviteAPI := invite.NewAPI(invite.NewService(db, baseURL), orgs, inviteCfg)

marketplace.NewAPI(humaAPI, marketplace.APIConfig{}, svc,
    marketplace.WithAuthorizer(authorizer))

// Mount each behind requestprincipal.Middleware so requests carry the caller.
```

With SpiceDB, pass the SpiceDB provider instead. `MembershipRoleGetter`
counts only active memberships; a role getter built on `GetMembership`
directly would also count deactivated ones.

### 3. Client changes

- Request fields that named the acting principal are optional and deprecated, and when sent must equal the caller: marketplace `purchaser_id`, `owner_id`, `assigned_by`; invite `inviter_principal_id` and `principal_id`; the `email` query on pending invites.
- Accepting or declining an invite requires the caller's email to match the invite.
- Listing organizations returns the caller's organizations (all of them for platform administrators).
- Creating an organization makes the caller its owner.
- Unpublished marketplace listings are visible only to the creator organization.

### 4. Go API changes

- Removed Ent schemas and packages: `user`, `membership`, `oauthaccount`, `refreshtoken`, `apikey`, `serviceaccount`, `serviceaccountkeypair`, and `mixin.UserBase` / `mixin.MembershipBase`.
- `systemauth.Storage` user methods became `CreateHuman`, `GetHuman`, `GetHumanByEmail`, `GetHumanByExternalIdentity`, `LinkExternalIdentity`, `UpdateHuman`, `DeleteHuman` on `HumanPrincipal`; `systemauth.User` and `ErrUserNotFound` / `ErrUserExists` are replaced by `HumanPrincipal`, `ErrPrincipalNotFound`, `ErrPrincipalExists`.
- OAuth tokens and authorization codes use the `subject` column; `OAuthConsent.user_id` is `principal_id`; `OAuthApp.owner` references `Principal`.
- `Human.email` is optional; `HumanPrincipal.Email`, `principal.Human.Email`, and contract identity types may be empty for a managed principal. Existing creation paths still require an email.
- `invite.Invite` has no `Token` field; the token is only in `InviteResult.InviteURL`.
- The `authz` providers are named for the mode they evaluate: `authz/simple` is now `authz/rbac` (role-based: roles plus direct grants), and `authz/spicedb` is now `authz/rebac/spicedb` (relationship-based, with SpiceDB as the engine). The old paths remain as deprecated forwarding packages for this release; change imports to the new paths, and `staticcheck` reports any you miss.
- `spicedb.BaseSchema` equals `authz.BaseSpiceDBSchema` and is deprecated: members hold `contribute`, not `edit`, on an organization, and editors are recognized.
- Interfaces gained methods: `authz.RelationshipSyncer` (`AddPrincipalManager`, `RemovePrincipalManager`) and `credential.Service` (`IssueLoginToken`, `VerifyLoginToken`).
- `organization.Service` `ListMembers` and `ListMemberships` exclude inactive memberships unless `IncludeInactive` is passed.
- `identity/token` returns typed errors: `ErrInvalidAccessToken`, `ErrInvalidRefreshToken`, `ErrRefreshTokenReused`, `ErrDPoPMismatch`, `ErrScopeNotGranted`.
- `marketplace.LicenseService` gains `GetByStripeSubscriptionID`.
- `identity/delegation` returns typed errors, `Link` gains `Active`, and an agent without a delegation is denied.
- `signup.SignupOrGetExisting` returns an existing account only when `SignupInput.EmailVerified` is set; `SignupWithInvite` requires the invited email.
- `apikey.Service` `Get`, `Revoke`, and `Delete` take the owning principal first; use `RevokeInOrganization` for an administrator of an organization-scoped key. A service with no `AllowedScopes` refuses keys that request scopes unless `AllowAnyScope` is set, and `MaxKeysPerUser` is enforced.
- `rls.Helper.SetTenant` and `SetUser` return `ErrNotInTransaction` for `*sql.DB` and `*sql.Conn`, because `SET LOCAL` outside a transaction scopes nothing. `rls.Middleware.SetRLSContext` only puts the caller on the request context; run queries through `Middleware.WithTx` or `rls.WithTenant`.
- `principal` lookups return `principal.ErrNotFound`; type-specific updates return `ErrWrongType`; `CreateAgent` returns `ErrInvalidDelegator`.

### 5. Behavior changes

- The default BFF session cookie is `sf_session` (was `cf_session`); browsers holding the old cookie sign in again.
- SCIM users are human principals; users provisioned before this release are not visible through SCIM. Managed principals are never SCIM users.

### 6. Stripe webhooks

Subscribe your Stripe webhook endpoint to
`checkout.session.async_payment_succeeded` in addition to
`checkout.session.completed`: licenses for delayed payment methods are now
granted when the payment clears, not when checkout completes. Subscribing
to `customer.subscription.deleted` makes cancellation revoke the license.

### 7. User authentication for the authorization endpoint

`systemauth.WithUserIDHeader` is removed, and `DefaultSessionProvider` no
longer believes any header on its own: it sends every authorization request
to the login URL. A deployment that relied on a gateway setting `X-User-ID`
must say so, and say which requests may be believed:

```go
gate, err := systemauth.TrustedProxyNetworks("10.0.0.0/8") // the gateway's addresses
if err != nil { return err }
provider := systemauth.NewDefaultSessionProvider(
    systemauth.WithTrustedUserIDHeader("X-User-ID", gate),
)
```

Use `systemauth.TrustAllRequests` only when the server is reachable solely
through a gateway that overwrites the header; the gate judges the direct
peer address, never `X-Forwarded-For`. Social login and custom
`SessionProvider`s need no change. `identity/oauth` takes
`oauth.WithUserAuthenticator` (or `WithTrustedUserIDHeader`) and
`WithConsent`; without them its authorization endpoint answers
`server_error` or `access_denied`.

### 8. Proxies, SCIM, federation, and introspection

- **Behind a reverse proxy**, tell SystemForge which proxies to believe, or every client will share the proxy's address: `ratelimit.ForwardedIPKey("10.0.0.0/8")` for limits, `bff.ClientIPConfig{TrustProxy: true, TrustedProxies: ...}` for sessions (and `CloudflareIPRanges` for Cloudflare), `systemauth.WithLoginTokenClientIP(...)`, and an `IPExtractor` for the API key middleware.
- **SCIM** now answers 403 until you pass `scim.WithAuthorizationHook` (for example `scim.NewScopedAuthorizationHook(true)`).
- **Federation**: pass `systemauth.WithFederationAuthenticator(systemauth.SharedSecretAuthenticator(secret))` to `NewFederationEndpoints`, or the sync and lookup routes are not registered.
- **Introspection**: resource servers must authenticate as a confidential client or present a token carrying the `introspect` scope.
- **Rate limiting** fails closed: a storage outage answers 503. Pass `ratelimit.WithFailOpen()` to keep the old behavior.
- **Tokens**: `session/jwt` and the contract middleware require `exp`; use `jwt.ValidateAccessTokenForAudience` or `middleware.HTTPAuthForAudience` on routes that serve one kind of client.
- **Lockout**: call `Lockout.Begin` before verifying a password and `Attempt.Success` or `Failure` after; `CheckAndRecord` is deprecated.
- **multiapp** apps that share a signing key should set `MiddlewareConfig.AppAudiences` and mint tokens with `jwt.TokenOptions{Audience: ...}`; apps with their own keys need nothing.
- **multiapp**: `AppAwareDB.ForSchema` returns an error; `SchemaDB.AcquireConn` is deprecated in favor of `Begin`.

### 9. Managed principals (optional)

Nothing changes unless you opt in. To enable, set `managed_principals.enabled`
in the SystemAuth configuration and `managed_principals: true` on each client
that may use them, then wire `identity/managedprincipal`. If you use the
marketplace, add `stripe.WithPurchaserChecker(managedPrincipalService)` so
managed principals cannot purchase.

## New Features

- `identity/managedprincipal`: `Create`, `AddManager`, `RemoveManager`, `ListManagers`, `ManagerRoles`, `IsManaged`, `IssueLoginToken`, `ListLoginTokens`, `RevokeLoginToken`, `ListSessions`, `RevokeSession`, `RevokeAll`, `IssueClaim`, `RedeemClaim`, `AttachVerifiedEmail`, and `NewHandler`.
- SystemAuth: `POST /login-token`, the `managed` claim, `Server.ManagedPrincipalsAllowed`, `Server.LoginTokenPolicy`, `WithCredentialService`, `WithLoginTokenRateLimit`.
- `identity/credential`: login tokens and `LoginTokenPolicy`.
- `authz`: `OrgRolePermissions`, `PermOrg*`, `ManagerRolePermissions`, `PermManage*`, `NewPrincipalResource`; `rbac.WithManagerRoleGetter`; `providertest.RunOrgPermissionTests` and `RunManagerRelationTests`; `spicedb.Client.DeleteRelationships` (now under `authz/rebac/spicedb`).
- `identity/requestprincipal`: `RequestPrincipal`, authenticator chain and middleware, `PrincipalUUID`; `aauthrs` for AAuth agents; `relyingparty.NewRequestAuthenticator`.
- `marketplace`: `WithAuthorizer`, `WithPurchaseAuthorizer`, `OrgRolePurchaseAuthorizer`, `WithCallerResolver`, `PurchaserChecker`; `stripe.WithPurchaserChecker`.
- `organization`: `MembershipRoleGetter`, `ErrMembershipNotFound`, `ListOrganizationsInput.MemberPrincipalID`.
- `identity/pgschema` (PostgreSQL `lower(email)` unique index), `identity/clientassertion` JWT ID replay protection, and `store.Config.TrustProvisionedEmail` for SCIM.

## Fixes

- The marketplace, organization, and invite APIs panicked at registration.
- The simple provider denied every organization permission check.
- SCIM listing panicked on every ascending sort.
- `identity/oauth.NewProvider` panicked on construction, and token revocation had no effect.
- `private_key_jwt` client authentication failed under foreign-key enforcement.
- A managed principal's first relying-party sign-in failed; empty emails could be matched or adopted; invite emails were compared case-sensitively; organizations created without a plan failed.

The complete list is in the [changelog](https://github.com/plexusone/systemforge/blob/main/CHANGELOG.md).
