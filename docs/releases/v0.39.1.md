# v0.39.1

**Release Date:** 2026-11-27

Authorization fixes in the marketplace. A license now grants access only to the
organization that holds it, and removing a member takes their seats with them.
Upgrade if an application uses `marketplace` license or seat checks.

## What was wrong

- **Unlimited licenses granted anyone access.** `CheckPrincipal` returned true
  for any principal when any organization held a valid unlimited license for
  the listing.
- **Seats outlived membership.** Removing a member left their seats on the
  organization's licenses, so they kept access.
- **A seat could be assigned during a removal.** An assignment that ran while
  the member was being removed could leave a seat behind.
- **An unassigned seat could stay in SpiceDB.** `UnassignSeat` could interleave
  with the graph write of an assignment.

## Changes to be aware of

- **Who a license covers.** `CheckPrincipal` and `AssignSeat` need an active
  principal in an active organization that holds an owner, admin or member
  membership, or a service, agent or application the organization owns.
  Collaborators are not covered. A person linked to an organization only as
  their home organization is not covered. See
  [who belongs](../marketplace/overview.md#who-belongs).
- **Seats need membership.** `AssignSeat` returns
  `marketplace.ErrNotOrganizationMember` for anyone else.
- **Custom authorizers.** The marketplace API's assign endpoint also needs the
  principal's membership row, not only the authorizer's permission.
- **Unassigning waits for the graph.** `UnassignSeat` removes the SpiceDB
  relationship before it commits. If SpiceDB refuses, the seat stays and the
  call can be retried.
- **Removal releases seats.** `RemoveMember` deletes the member's seats on the
  organization's licenses and frees them.

## Upgrading

There is no new migration since v0.39.0.

1. A deployment that writes seats to SpiceDB passes the syncer to the
   organization service, or removed members keep their `seat_holder`
   relationships:

    ```go
    orgs := organization.NewService(client,
        organization.WithSeatSyncer(marketplace.NewSpiceDBSyncer(spice)),
    )
    ```

2. Code that calls `AssignSeat` directly handles
   `ErrNotOrganizationMember`.
3. Seats already held by people removed before this release stay in the
   database and in SpiceDB. They grant nothing through `CheckPrincipal` unless
   the organization owns the principal. Unassign them to free the seats and
   remove the relationships.

## Known limitations

- Revoking a license does not remove its seat relationships from SpiceDB.
  Unassign the seats before revoking.
- The SCIM setup in `systemauthsvc` does not set a seat syncer.
- If the SpiceDB write after an assignment fails, retrying returns "already
  assigned". Unassign the seat, then assign it again.
- A service account that holds a seat cannot be deleted until the seat is
  unassigned.

See [the marketplace guide](../marketplace/overview.md#seat-management).
