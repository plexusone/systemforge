# v0.34.0

**Release Date:** 2026-11-12

A sign-out can land where the person signed in: a child signed in with a
login token on a shared device goes back to the app's sign-in page, while
adults keep landing on the product's site. Entitlements can also follow
billing's free mode, resolving the known issue of [v0.33.0](v0.33.0.md).

## Where a child's sign-out lands

- **`social_login.managed_signed_out_url`.** A session signed in with a
  managed principal's login token, such as a child's, lands there when it
  signs out, in place of `signed_out_url` and whatever `return_to` the app
  sent. Every other sign-out is unchanged: it lands on `signed_out_url`, or
  on the app's `return_to` without one.
- **The decision is SystemAuth's.** It reads the session it is ending, so
  apps keep posting the same sign-out form and need no change. A sign-out
  without a session is not treated as managed.
- **The URL must pass the redirect allowlist,** as `signed_out_url` does: a
  path on the issuer or an origin in `allowed_redirect_origins`. An unlisted
  URL is refused at startup.

See [Social login](../systemauth/social-login.md) and
[Relying parties](../systemauth/relying-party.md).

## Entitlements in free mode

- **`marketplace.WithoutPayments()`.** `marketplace.EntitlementSource`
  granted a paid plan stored on a subscription even when the deployment
  takes no payments, unlike `OrganizationPlan`. With the option, a
  subscription grants only a plan the operator set.
- **`Service.TakesPayments()`** reports whether billing takes payments: the
  configuration has a `billing` section with a Stripe key.
- **The free-mode log** at startup says that an operator's plan still
  applies.

The release adds no breaking change.

## Upgrading

To send children back to the app's sign-in page, list the page's origin in
`allowed_redirect_origins` and set the new field next to `signed_out_url`:

```yaml
social_login:
  allowed_redirect_origins:
    - https://app.example.com
    - https://www.example.com
  signed_out_url: https://www.example.com/
  managed_signed_out_url: https://app.example.com/
```

Leaving it unset keeps every sign-out as before.

A host that builds `marketplace.EntitlementSource` over the platform
subscription passes the option when payments are off:

```go
opts := []marketplace.EntitlementOption{}
if !svc.TakesPayments() {
    opts = append(opts, marketplace.WithoutPayments())
}
src := marketplace.EntitlementSource(subs, licenses, listings, opts...)
```

Without the option `EntitlementSource` behaves as before, which suits a
host that takes payments outside SystemForge's billing.
