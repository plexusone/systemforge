    Changelog¶

    All notable changes to this project will be documented in this file.

    The format is based on Keep a Changelog, this project adheres to Semantic Versioning, commits follow Conventional Commits, and this changelog is generated by Structured Changelog.

    Unreleased¶

    v0.18.0 - 2026-10-20¶

    Highlights¶

    • SystemAuth serves the organization console under /console, where organizations manage their connections to external services, signed in with the SystemAuth login session
    • The connections API records the rotation mode chosen when connecting, from the provider manifest's guidance

    Upgrade Guide¶

    • To enable the organization console, set console.web_dir to a build of @plexusone/console; social login must be configured
    • To offer the console from an application's chrome, list it in the app catalog with the ID console

    Added¶

    • console package: the connections API under /console/api with a login-session authenticator, session routes, return-address checks, and built pages served with a sign-in redirect; state-changing requests must be same-origin and every response carries a restrictive content security policy (e901768)
    • console.web_dir in the SystemAuth configuration; a console without social login is refused (fbf6773)
    • systemauthsvc mounts the organization console when configured, listing organizations from the orgs claim and including connections when they are enabled (5e7f85e)
    • Console session routes under /console/bff in the format @plexusone/host reads: GET session, sign-in redirects and POST auth/logout; each organization grants the console application the person's organization role (25fc039)
    • The console's session lists each organization's product roles and carries the app catalog, so the console's product switcher links back to the products (4e2609a)
    • systemauth.Server.ValidateReturnTo accepts a return address only where the sign-in redirect policy allows (57307ca)
    • systemauth.Server.EndLoginSession signs a person out as POST /logout does, for handlers that check the request's origin themselves (4c74b57)
    • Connect requests accept an optional rotation mode from the auth method's manifest, kept in the connection's metadata under rotation; an unlisted mode is refused (15f4b5d)

    Dependencies¶

    • 2 dependency updates

    Documentation¶

    • ADR-018: the organization console on the SystemAuth host (bc54dc6)
    • Organization console guide: configuration, pages, session routes, API and linking from the app catalog (a8fefa5)
    • Connections guide covers setup steps, rotation modes and credential expiry
    • v0.18.0 release notes

    Tests¶

    • Cover the organization console, return-address checks, the session format, sign-in and sign-out, and product roles and the catalog in the session (59a6a62)
    • Cover recording the rotation mode (194db85)
    • Cover ending a login session from another handler

    v0.17.0 - 2026-10-18¶

    Highlights¶

    • Relying-party applications manage managed principals through SystemAuth: a /managed-principals API served by systemauthsvc, called with the manager's access token, and the mpclient Go client
    • Nobody becomes a manager without agreeing: managers other than the creator join by invitation or claim
    • The contract's identity, policy and audit operations refuse requests until the application is federated

    Upgrade Guide¶

    • Standalone applications that serve the contract API: set Config.AllowUnauthenticatedStandalone in development and tests, or federate the application; identity, policy and audit operations otherwise answer 403
    • Code calling managedprincipal.Service.Create with managers other than the actor, or AddManager: invite those managers or issue a claim, or build the service with WithDirectManagerAdds for administrator tooling
    • Managers in roles registered with WithRoles can no longer issue login tokens; issue them as a guardian or educator
    • To let a relying party manage managed principals, enable managed_principals for the deployment and its client and add systemforge:managed_principals to the client's scopes

    Added¶

    • SystemAuth built by systemauthsvc serves the managed-principal API at /managed-principals when managed principals are enabled, for relying parties calling with a manager's access token granted systemforge:managed_principals; Options.AuditEmitter, ManagedPrincipalRates and ManagedPrincipalOptions, and Service.ManagedPrincipals() (a76d041)
    • managedprincipal.NewHandler relying-party mode (WithRequestClient): the client is the access token's, creation names only the caller, unknown and unmanaged principals answer 403; WithCodeRateLimit for code routes; GET / (Service.ListManagedBy) and POST /{id}/login-tokens (af30b5b)
    • managedprincipal/mpclient, a typed client for the managed-principal API with errors wrapped in *APIError (eaca813)
    • systemauth.Server.BearerAccess and BearerAuthenticator: bearer access that carries the token's client, scopes and grant, adapted to requestprincipal (c0c4e8d)

    Changed¶

    • BREAKING: The contract's identity, policy and audit operations answer 403 until the application is federated; Config.AllowUnauthenticatedStandalone restores the open behavior for development and tests (9883be5)
    • BREAKING: managedprincipal.Service.Create accepts only the actor as manager and AddManager is refused with ErrConsentRequired, so managers join by invitation or claim; WithDirectManagerAdds keeps direct adds for administrator tooling (53a2655)
    • Issuing a login token requires manage_credentials (bf1c347)
    • The managed-principal handler answers 403 for an unknown or unmanaged principal, as for one the caller does not manage (0124078)

    Documentation¶

    • Managed principals guide covers the API on SystemAuth, its configuration and scope, and the client
    • INIT-SYSTEMFORGE-012 specification for managed principals in relying-party applications (a18e9f1)
    • v0.17.0 release notes; relying-party, embedding and README updates for the managed-principal API

    Tests¶

    • The connections test checks the error RunJobs returns when its context ends (078231b)

    v0.16.0 - 2026-10-14¶

    Highlights¶

    • Connections can be reconnected in place, track what depends on them with bindings, and be shared with a principal through per-connection role grants
    • The connection library is renamed from connectionforge to connectforge; imports, tables (connectforge_*) and the key purpose (connectforge.credential) change, which is breaking for deployments that enabled connections in v0.15.0

    Upgrade Guide¶

    • Update imports from connectionforge to connectforge
    • Deployments that enabled connections in v0.15.0 must re-create connections or rename the tables and re-seal credentials; migrate does not copy rows or re-seal
    • Run systemauth migrate to create the connectforge_* tables

    Added¶

    • POST .../connections/{id}/reconnect, GET, PUT and DELETE .../connections/{id}/bindings, and GET, PUT and DELETE .../connections/{id}/grants/{principal} (5a4bf33)
    • systemauthsvc registers the systemforge_connection resource type so connection grants are role grants read by the role-based provider (8f501c3)

    Changed¶

    • BREAKING: Depend on connectforge instead of connectionforge; tables are now connectforge_* and credentials are sealed under the connectforge.credential purpose (7eb410b)

    Dependencies¶

    • 1 dependency update

    Documentation¶

    • Connections guide covers reconnecting, bindings and grants; ADR-017 updated for the rename and the grant vocabulary (0a5c80b)

    Tests¶

    • Cover reconnect, bindings and grants over the API (26d6b64)

    v0.15.0 - 2026-10-13¶

    Highlights¶

    • Key management: keys wires keyforge as the platform's one key library, with envelope encryption, rotation without re-encrypting, the root key read through omnivault, and key events sent to the audit trail (ADR-013)
    • Connections to external services: connections composes connectionforge so organizations connect accounts at services such as a CDN or analytics product, with credentials sealed under managed keys and applications receiving an authenticated HTTP client, never the secret (ADR-017)
    • A connections API at /api/v1/organizations/{org}/connections, enabled by the new connections configuration section and protected by systemforge:connections:read and :write scopes
    • Invite-only sign-up: a gate on social login that admits only verified emails holding an invite, a consent-recording waitlist for everyone else, and systemauth invite and systemauth waitlist commands
    • App catalog: a host publishes the applications it runs, and the browser session lists it so each shell can show the products a person holds a role in, for a product switcher
    • Embedded SystemAuth emits the orgs claim with per-application roles, limited to the deployment's default entitlements
    • Fixed rls.Helper.SetTenant and SetUser, which failed on every PostgreSQL connection because SET LOCAL does not accept bind parameters
    • No breaking changes; run systemauth migrate for the new tables

    Upgrade Guide¶

    • Run systemauth migrate (or systemauthsvc.Service.Migrate) to create sf_signup_invites and sf_signup_waitlist. Existing tables are unchanged and no SQL migration file is needed
    • To enable connections, add the connections section, create the root key (openssl rand -base64 32) and store it in the vault, and back up keys_dir with the database. systemauth migrate then creates the connectionforge_* tables and enables row-level security on PostgreSQL

    Added¶

    • keys package: Open, Seal and Open over keyforge's single-host setup, with VaultSource reading the root key from an omnivault vault, and an audit sink that records lifecycle events without key material (1f3095e)
    • connections package: connectionforge's SQL store on the platform database with row-level security keyed on owner_id, credentials sealed by keys, deployment secrets read from omnivault, authorization through authz, and audit events to the platform trail (5975b1e)
    • connections.RolePermissions grants organization owners and admins view, use and manage on connections, and members view (dfcd4ed)
    • connections.Handler: the organization-scoped connections HTTP API (providers, list, connect, get, rename, test, disconnect) that never returns a credential and reports a refused view as not found (dfcd4ed)
    • connections.MigrateSchema creates the connection tables and enables row-level security without opening the keys, so systemauth migrate needs no root key (dfcd4ed)
    • systemauth.Server.BearerPrincipal and WriteBearerError authenticate API requests by bearer access token and scope with RFC 6750 responses (ccc1d03)
    • connections section of the SystemAuth configuration (keys_dir, vault, root_key, allow_private_egress), the systemauthsvc.Options.Providers registry, Service.Connections and Service.RunJobs (7b51e06)
    • systemauth serve runs the key lifecycle jobs while serving (dfb3597)
    • systemauth invite add|list|revoke and the --invite-only and --signup-denied-url flags, with SignupInvite (sf_signup_invites), the signupgate store and gate, and systemauth.SignupGate on social login (3471a81)
    • For host binaries: systemauthsvc.Options.InviteOnly, SignupDeniedURL and WaitlistPage, Service.SignupInvites and Service.SignupWaitlist, and the signupgate/signupcmd package with the invite and waitlist command groups to mount in a host's own CLI (dc2af08)
    • Sign-up waitlist: /signup/waitlist records an address with the consent text shown and its version, with SignupWaitlistEntry (sf_signup_waitlist), signupgate.Waitlist and systemauth waitlist list [--csv] and remove (72ac85b)
    • appcatalog package: App and an ordered, validated Catalog, with Static and Remote sources, the last cached and kept through an outage (538133c)
    • systemauth.WithAppCatalog serves the catalog at /.well-known/sf-apps; relyingparty.BFFConfig.Apps adds the catalog to /bff/session as apps, which a shell filters by the membership's applications; systemauthsvc.Options.Apps publishes a host's catalog and warns about entries with no registered vocabulary (31cc7a9)
    • systemauthsvc.Options.Vocabularies and DefaultEntitlements install an Ent-backed orgs claim source with application roles from approle (cffe439)

    Fixed¶

    • rls.Helper.SetTenant and SetUser use set_config(name, value, true), which has the transaction scope of SET LOCAL and takes the value as a parameter; the previous SET LOCAL ... = $1 was a PostgreSQL syntax error (6149cc1)

    Dependencies¶

    • 2 dependency updates

    Documentation¶

    • Guides for connections to external services and for key management, and sections for them in the deployment guide and README (ee8b6d7)
    • Deployment guide sections for invite-only sign-up with the waitlist, and for the app catalog (2190863)
    • ADR-017 on external connections, ADR-016 on no static API keys and ADR-015 on identifier policy, slug namespaces and portability (cac014f)
    • ADR-013 makes keyforge the platform's key library, with the key subsystem, rotation policy, hybrid encryption, FIPS 140-3 and post-quantum positions, rotation and recovery drills, and the crypto specification; ADR-011 and ADR-012 add purge, provisional accounts, dormancy and offload (5460d4f)

    Tests¶

    • rls is checked against a real PostgreSQL server, and the connections store is checked as an ordinary database role, which row-level security applies to (77b8d12)
    • The connections API is exercised end to end against a fake provider, including that no response carries a token (b9bb2db)

    v0.14.0 - 2026-10-11¶

    Highlights¶

    • Managed principals: humans without an email, such as young learners, created and controlled by guardian and educator managers, who sign them in with QR-friendly login tokens; opt-in per deployment and per client (ADR-005)
    • Principal is the sole identity root: the legacy User model and its dependent tables are removed, so password login, social login, federation sync, and SCIM all resolve a person to the same principal (ADR-004)
    • Resource servers can authenticate AI agents with AAuth through a protocol-neutral request principal and authenticator chain shared with bearer, API-key, and BFF-session credentials
    • Fixed a panic on every ascending SCIM list sort, including the default order
    • Security: the marketplace, organization, and invite APIs act for the authenticated caller and check organization permissions, instead of trusting IDs in the request; invite tokens are stored hashed
    • The simple and SpiceDB authorization providers grant the same organization and manager permissions, held to the base schema by a parity test and a shared conformance suite
    • Organizations without a plan: a first social login creates the person's personal organization, slugs are reserved, renamed with a cooling-off period and aliases, a personal organization converts to a team, and what an organization may use comes from its marketplace subscriptions and licenses (ADR-006)
    • Application roles per member, entitled through the marketplace, carried in the orgs claim and on invites, with relying parties reading memberships from claims by default (ADR-007)
    • Real-time invalidation of access: access tokens default to 10 minutes and are capped at 15, every access-reducing change is recorded, and relying parties refuse tokens issued before it, with polling, replay and back-channel delivery (ADR-010)
    • Resource-scoped collaborators: the collaborator organization role, resource grants with a standard viewer, contributor and maintainer ladder in both authorization modes, and invites that target one resource (ADR-008)
    • The authorization mode is configuration: the authz key selects rbac or rebac, and authz/mode.New builds the provider, syncer and grant store (ADR-008)
    • Management is derived from manager relationships; a manager can release a principal, a self-managed human can be invited to be managed or decline, and managing operations are authorized and served over HTTP (ADR-009)
    • Editor and viewer are no longer organization roles, and the organization plan column is removed; run migrations 0004 to 0009 on existing PostgreSQL databases

    Breaking¶

    • Removed Ent schemas and packages user, membership, oauthaccount, refreshtoken, apikey, serviceaccount, and serviceaccountkeypair, with the Organization memberships, api_keys, and service_accounts edges and OAuthToken.service_account_id (05d78ae)
    • systemauth.Storage user methods are replaced by CreateHuman, GetHuman, GetHumanByEmail, GetHumanByExternalIdentity, LinkExternalIdentity, UpdateHuman, and DeleteHuman on one HumanPrincipal type; systemauth.User, LoginPrincipal, ErrUserNotFound, and ErrUserExists are removed in favor of HumanPrincipal, ErrPrincipalNotFound, and ErrPrincipalExists (d054dc7)
    • OAuthApp.owner references Principal; statically configured clients are owned by a service principal at the fixed system ID instead of a synthetic user (12f2494)
    • OAuth tokens and authorization codes drop user_id and the user edge in favor of the subject column; OAuthConsent.user_id becomes principal_id (16f7f9f)
    • SCIM users are human principals and group membership uses PrincipalMembership; users provisioned before this release are not visible through SCIM (6a12bae)
    • An existing PostgreSQL development database must run migrations/0002_drop_legacy_user_tables.sql before starting this version; fresh databases need no migration (97282d7)
    • The default BFF session cookie is sf_session instead of the Core-era cf_session; browsers holding the old cookie sign in again. Applications that set CookieConfig.Name are unaffected (94868b5)
    • organization.Service ListMembers and ListMemberships exclude inactive memberships unless IncludeInactive is passed, and take variadic ListOption arguments (3f80884)
    • mixin.UserBase and mixin.MembershipBase are removed (8c95e08)
    • Human.email is optional: a human without one is a managed principal with the identifier human:. HumanPrincipal.Email, principal.Human.Email, and contract identity types treat it as optional; existing creation paths still require an email (e89af69)
    • Marketplace checkout buys as the authenticated caller for an organization the caller may buy for, and answers 501 until marketplace.WithPurchaseAuthorizer or WithAuthorizer is configured; purchaser_id is optional, deprecated, and must equal the caller (7cf758e)
    • Marketplace listing and license operations answer 501 until marketplace.WithAuthorizer is configured and require an authenticated caller; only published listings are readable anonymously; owner_id and assigned_by are optional, deprecated, and must equal the caller (bbac538)
    • Organization API endpoints require an authenticated caller and, except creating an organization and checking a slug, answer 501 until APIConfig.Authorizer is set (08bd206)
    • Invite API endpoints require an authenticated caller and organization endpoints answer 501 until APIConfig.Authorizer is set; accepting and declining require the invite to be addressed to the caller's email; inviter_principal_id, principal_id, and the email query are optional, deprecated, and must match the caller (236c0e9)
    • Invite tokens are stored hashed and invite.Invite no longer has a Token field; the token is only in InviteResult.InviteURL. Existing PostgreSQL databases run migrations/0003_hash_invite_tokens.sql when deploying (7ccc80e)
    • spicedb.BaseSchema is now authz.BaseSpiceDBSchema: members hold contribute rather than edit on an organization, and editors are recognized (8762bc6)
    • authz.RelationshipSyncer gains AddPrincipalManager and RemovePrincipalManager; credential.Service gains IssueLoginToken and VerifyLoginToken; managedprincipal.Gate implementers also provide LoginTokenPolicy (8acce83)
    • identity/token reports typed errors (ErrInvalidAccessToken, ErrInvalidRefreshToken, ErrRefreshTokenReused, ErrDPoPMismatch, ErrScopeNotGranted) (2a3c8cd)
    • marketplace.LicenseService gains GetByStripeSubscriptionID; Stripe webhook endpoints should also subscribe to checkout.session.async_payment_succeeded (fa2a57d)
    • delegation errors are typed and an agent without a delegation is denied; signup's SignupOrGetExisting requires SignupInput.EmailVerified to return an existing account, and SignupWithInvite requires the invited email (284806d)
    • systemauth.WithUserIDHeader is removed; use WithTrustedUserIDHeader with a RequestGate (TrustedProxyNetworks or TrustAllRequests), social login, or your own SessionProvider. DefaultSessionProvider authenticates nobody by default (645c151)
    • identity/oauth's authorization endpoint refuses requests until WithUserAuthenticator or WithTrustedUserIDHeader is set, and third-party clients are refused until WithConsent is set (ef7ea3d)
    • session/ratelimit: IPKey and the Limiter default no longer read X-Forwarded-For or X-Real-IP (use ForwardedIPKey or ForwardedClientIP behind proxies), the middleware answers 503 on storage errors unless WithFailOpen is given, and MemoryStorage returns ErrTooManyKeys when full (3019061)
    • session/bff: TrustProxy and TrustCloudflare do nothing without TrustedProxies or CloudflareIPRanges; session/middleware no longer reads forwarding headers for API key usage addresses unless an IPExtractor is given (a253f24)
    • scim: a provider without WithAuthorizationHook answers 403 to every request; DefaultAuthorizationHook is deprecated for AllowAllAuthorizationHook (0e3dd33)

    Upgrade Guide¶

    • Run the migrations against an existing PostgreSQL database, in order: 0004_drop_organization_plan, 0005_subscriptions_per_listing, 0006_invite_app_roles, 0007_oauth_app_backchannel_logout_uri, 0008_drop_editor_viewer_roles and 0009_invite_resource_target. Each is idempotent. Fresh databases need none of them. Then run systemauth migrate for the new tables sf_app_roles, sf_slug_reservations, sf_access_changes, sf_resource_grants and sf_manager_invites
    • Replace uses of the organization plan with entitlements: remove Plan from organization inputs and filters, and read entitlements from organization responses. Supply APIConfig.Entitlements with marketplace.EntitlementSource; carry a paid tier over as a subscription or license
    • Replace editor and viewer in your own role tables, vocabularies and invites with member and collaborator (or resource roles); stored memberships are mapped by migration 0008, which records an access change for each active membership it changes
    • Configure entitlements for application roles: build the approle service with marketplace.ApproleOptions(marketplace.EntitlementSource(...)), and declare applications free to everyone with marketplace.WithDefaultEntitlements. Without them no organization is entitled to anything, and marketplace.WarnIfNoEntitlements logs a startup warning
    • Relying parties that depended on LocalMemberships must pass it explicitly. The default reads the orgs claim; use ClaimsOrRemoteMemberships to fall back to /oauth/userinfo/memberships when the claim is truncated or absent
    • Pass a revocation cache to BearerMiddleware and NewBFF to refuse tokens issued before an access change; feed it with accesschange.ToSink in one process, the poller across replicas, or back-channel delivery across deployments. Review any configured access_token_lifetime against the 15 minute cap
    • Build the authorization provider from configuration with authz/mode.New(ctx, cfg.Authz, mode.Deps{...}) and pass its Syncer to the identity services. The authz key defaults to rbac. The authz/simple and authz/spicedb forwarding packages remain deprecated and will be removed in the next major release; import authz/rbac and authz/rebac/spicedb
    • When switching to rebac, write existing memberships, application roles and resource grants into the graph through the syncer before serving requests, and write the composed schema (embedded instances always receive it; remote ones only with write_schema)

    Security¶

    • Marketplace checkout took the purchaser from the request body, so anyone could start a purchase in another principal's name for any organization (7cf758e)
    • Marketplace listing, license, and seat endpoints acted on any IDs a request named; they now check the caller's permissions on the owning organization (bbac538)
    • The organization API listed every organization and let any caller read, change, or delete organizations, change members, and transfer ownership; it now authorizes each operation (08bd206)
    • Invite management needed no permission, and anyone holding an invite link could accept it as any principal; invites are now managed with invite_member and accepted only by the addressee (236c0e9)
    • Invite tokens were stored in plain text, so a leaked table or backup could accept invites; they are stored as SHA-256 hashes (7ccc80e)
    • SpiceDB principal and organization cleanup ignored failures and missed editor and manager relations, leaving access behind while reporting success (22f7b28)
    • Refresh-token rotation was not atomic and its revocation error was discarded, so a refresh token could be used more than once; refreshing near expiry also reset a session to seven days, extending it indefinitely. Rotation is now atomic, a family keeps its first expiry, and reusing a rotated refresh token revokes the family (2a3c8cd)
    • Stripe checkout granted licenses for sessions completed with an unpaid delayed payment, a malformed seat count produced an unlimited seat-based license, and cancelled subscriptions kept their licenses (fa2a57d)
    • Deactivating a principal left its access tokens valid and let its refresh tokens keep issuing new ones for up to the family's absolute lifetime; SystemAuth and identity/token now refuse an inactive principal's tokens wherever they are used or refreshed, and revoke the family (ebe913d)
    • Revoking an agent's delegation gave it unrestricted access, constraints that did not overlap allowed everything, and delegation expiry and action limits were never stored; delegation now fails closed and enforces every constraint (284806d)
    • UpdateHuman granted or revoked platform administration without syncing it, so a revoked administrator stayed one in SpiceDB (5e002b3)
    • SignupWithInvite let anyone holding an invite link join under any email, and SignupOrGetExisting returned an existing account for an unverified email (e6d07df)
    • SystemAuth's default session provider and identity/oauth's authorization endpoint took the user from an X-User-ID request header, so anyone who could reach the endpoint could obtain an authorization code, and tokens, for any user; header identity is now an explicit, gated opt-in and the default authenticates nobody (645c151)
    • identity/oauth granted every requested scope to every client without consent; non-first-party clients now need a consent check (ef7ea3d)
    • SCIM listing and search never asked the authorization hook, so any caller with a token could dump every user and group, and the provider's default hook allowed everything; listings are authorized and the default denies (0e3dd33)
    • The federation identity sync endpoint trusted any well-formed request and acted on its body, letting an unauthenticated caller link to and then deactivate or rewrite any account by email; it and the lookup endpoint now require a FederationAuthenticator and are not registered without one (d57bf0f)
    • Rate limits keyed on client-supplied X-Forwarded-For and X-Real-IP, so a client could evade a limit by rotating the header or poison a victim's; they key on the direct peer, and forwarded headers are believed only from configured trusted proxies, here and in the BFF client IP handling and the API key middleware (3019061)
    • The in-memory rate-limit store grew without bound from attacker-chosen keys, the middleware failed open on storage errors, and the login token endpoint keyed on raw client_id values; the store is bounded, the middleware fails closed, and only registered clients get a bucket (3019061)
    • Token introspection accepted any valid access token or any client's Basic credentials, public clients included, as the caller's credential; it now requires a confidential client or a token with the introspect scope (5e6dba0)
    • The default storage accepted every client-assertion JWT ID as new, so a captured private_key_jwt assertion could be replayed until it expired (2ae4f56)
    • BFF cookies lost Secure and HttpOnly when a CookieConfig omitted them; both are now unconditional unless AllowInsecure is set for development (d1d897c)
    • Cookie-authenticated writes through relyingparty.BearerMiddleware skipped the same-origin check, allowing cross-site requests (ebf1095)
    • JWT validation accepted tokens with no expiry and ignored the issuer; the contract middleware did the same and skipped the audience check without an app ID (7061c67)
    • Client secret validation revealed whether a client ID existed by error message and timing, and lockout counted differently spelled identifiers separately, restarting the count (30bd958)
    • multiapp's SchemaDB left a schema's search_path on pooled connections, which could carry one application's schema to unrelated code, and ForSchema interpolated unvalidated names into SQL (012e2db)
    • The BFF proxy forwarded the browser's session cookie upstream when a ProxyConfig was built by hand; Cookie, Authorization, and DPoP headers are now always stripped (3c54fc2)
    • multiapp trusted the X-App-ID header, so with a shared signing key a token for one app authenticated requests for another; MiddlewareConfig.AppAudiences binds tokens to the routed app (73e0d19)
    • API keys could be read, revoked, or deleted by ID alone, requested any scope including the wildcard when no allow-list was set, and ignored MaxKeysPerUser (0a3cf11)
    • Lockout let a burst of parallel guesses exceed MaxAttempts; Lockout.Begin reserves the attempt before the credential is verified (43c3818)
    • Concurrent BFF refreshes spent one refresh token several times, which token reuse detection treats as theft; refresh is now serialized per session (a77d8df)
