    Changelog¶

    All notable changes to this project will be documented in this file.

    The format is based on Keep a Changelog, this project adheres to Semantic Versioning, commits follow Conventional Commits, and this changelog is generated by Structured Changelog.

    Unreleased¶

    v0.23.0 - 2026-10-27¶

    Highlights¶

    • aauthrs accepts auth tokens only from their rightful issuer: in four-party only the Audience Access Server, in three-party only a trusted Person Server issuing for itself, so a Person Server trusted for person tokens can no longer grant itself scopes that bypass the Access Server
    • aauthrs refuses a request signed for another server, so an agent's signed request cannot be replayed to a resource it was not meant for
    • Updates aauth-go to v0.3.0

    Breaking¶

    • aauthrs: an Access Server's auth tokens are accepted only when it is named in Config.Audience; listing it in TrustedIssuers no longer admits them, and a trusted issuer's auth token with dwk aauth-access.json is refused in three-party (051e23b)

    Upgrade Guide¶

    • A resource that accepts auth tokens from an Access Server sets aauthrs.Config.Audience to it; when the Person Server and Access Server share one origin, name it in both TrustedIssuers and Audience
    • An application that also depends on aauth-go directly reviews its v0.3.0 migration guide: agent identifiers must be in their provider's domain, and servers built on its personserver and accessserver stores gain new methods

    Security¶

    • aauthrs enforces who may issue an auth token, which aauth-go leaves to the caller; before, any issuer in TrustedIssuers was accepted with either dwk (051e23b)
    • aauthrs defaults Signature.Authority to the host of Resource, so a verified signature is bound to this resource; agent tokens carry no audience, so a request signed for another server could otherwise be replayed in agent-token mode (4adc9f4)

    Added¶

    • aauthrs.Config.IsRevoked, asked about every token once it and the request signature verify: a revoked token is a 401 revoked_jwt, unavailable revocation state a 500, as in aauth-go's ResourceGuard (e9ac963)

    Dependencies¶

    • 1 dependency update

    Documentation¶

    • The AI Agents (AAuth) guide covers Audience, the signature authority, IsRevoked, and choosing three- or four-party (36d4c69)
    • v0.23.0 release notes

    Tests¶

    • Cover the auth-token issuer rules in three- and four-party, a request signed for another server, and the revocation hook (3ae1567)

    v0.22.0 - 2026-10-25¶

    Highlights¶

    • Invite-gated sign-up grows a deployment on purpose: operators create invite codes with use limits, expiry and cohort labels, members invite people from an allowance, every account records which invite admitted it, and an HTTP API serves admin and member pages

    Added¶

    • signupgate.CodeStore: invite codes stored as hashes and shown once, reserved with one conditional update so a code admits at most its use limit, redemptions for attribution, and member allowances with single-use member codes (8ffe82f)
    • systemauth.WithSignupCodes: the /signup?code= page and invite_code on provider sign-in carry a code to the sign-up gate; SignupGateAborter lets a gate give back a reservation when account creation fails (89d2b55)
    • signupgate/signupapi: operator routes for email invites, codes, the waitlist, allowances and joined accounts, and member routes for a person's own codes, with audit events (1551e8a)
    • systemauthsvc options SignupCodes, SignupPage, MemberInvites and SignupAPI, and Service.SignupCodes and Service.SignupAPI (93915ad)
    • Commands code, allowance, waitlist invite and admin (principal/admincmd) for operators, including granting the first platform administrator (e75977e)
    • Migration 0011 records who created a sign-up invite and when a waitlist entry was invited (f7ee741)

    Documentation¶

    • Invite-Gated Sign-Up guide (bb60e66)

    v0.21.0 - 2026-10-25¶

    Highlights¶

    • Tokens are DPoP-bound by default: SystemAuth and the identity/oauth provider verify DPoP proofs (RFC 9449) at the token endpoint and bind access and refresh tokens to the proof's key, the relying-party, session and multi-app middleware accept a bound token only with a proof by its key, and the BFF presents tokens with proofs by the session's key; unbound bearer tokens remain only as an explicit per-client opt-out (allow_bearer_tokens)
    • Keys and secrets rotate N / N-1: JWT signing keys carry key IDs and pre-staged verification keys, and client secrets, BFF session sealing keys and SCIM tokens keep the current and previous value valid, so a rotation can be rolled back without signing anyone out
    • Built-in per-tenant SCIM tokens: the scimtoken store issues, rotates and revokes hashed tokens bound to one organization, and the packaged SystemAuth service serves SCIM 2.0 and token management with them
    • Revocations reach the ReBAC graph first: removing access deletes the relationships under advisory graph locks before the database change commits and fails when the graph refuses, a reconciler repairs the graph from the identity tables, and the packaged service runs in mode rebac
    • Each multi-app application connects with its own database login, verified at startup to be confined to its schema, reads the shared identity tables read-only, and is migrated by a separate step that keeps the owner login out of app servers

    Breaking¶

    • systemauth: token requests without a DPoP proof are refused unless the client sets allow_bearer_tokens; tokens are DPoP-bound and must be presented with the DPoP scheme and a proof. Existing databases need migrations/0010_oauth_app_allow_bearer_tokens.sql. EmbeddedOAuthProvider.UserInfo refuses DPoP-bound tokens, and AuthorizeIntrospectionCaller also accepts the DPoP scheme
    • systemauth: a token subject must be a principal ID; tokens for other subjects are refused, and custom Storage implementations must implement PrincipalActive
    • systemauth: a client secret older than the two newest active secrets no longer authenticates
    • systemauth: WithAccessChanges takes an AccessChangeScope; without one /access-changes answers 501
    • systemauth: EntStorage.UpdateHuman with Active false fails, and the principal stays active, when the graph refuses to remove its relationships, and it records a deactivation access change
    • oauth: clients without allow_bearer_tokens must send DPoP proofs and present tokens with the DPoP scheme; NewProvider requires Config.PrivateKey or AllowEphemeralKey; API.Middleware panics without WithAcceptedClientIDs or WithAnyClient; Provider.Session returns *systemauth.Session
    • token: IssueInput.DPoPJKT and RefreshInput.DPoPJKT are replaced by DPoP *dpopproof.Proof, and bound tokens have TokenType DPoP
    • relyingparty: BearerMiddleware and RequestAuthenticator panic when Tokens is set without BearerConfig.DPoP or AllowBearerTokens, and always refuse a DPoP-bound token sent as Bearer; relying-party instances sharing sessions must share Config.DPoPKey
    • session/middleware: HTTPAuth, HTTPAuthForAudience, HTTPAuthOptional, ChiAuth and ChiAuthOptional take a DPoPConfig, return an error and refuse unbound tokens unless DPoPConfig.AllowBearer is set; the bearer-only middleware is renamed HTTPAuthBearer and its variants
    • session/middleware: APIKeyMiddleware panics without OwnerCheck, and RequireAPIKey, RequireAPIKeyWithScopes and OptionalAPIKey take an APIKeyOwnerCheck
    • session/jwt: NewService fails with ErrMissingIssuer without Config.Issuer and with ErrWeakSecret for an HMAC secret shorter than the hash output
    • multiapp: AuthMiddleware returns (middleware, error), needs MiddlewareConfig.JWTService and DPoP.ReplayCache, and refuses unbound tokens unless DPoP.AllowBearer is set
    • multiapp: every app needs its own database login in Config.AppDatabases; Config.DatabaseURL is removed, MigrationDatabaseURL is refused without AllowInProcessMigrations or AllowSharedDatabaseLogin, RegisterApp fails when the app schema is missing, and an AppAwareDB serves one schema unless opened with AllowSharedLogin or AsMigrationLogin
    • multiapp: RoleProvisioning with nil SharedReadTables, and multiappdb without --shared-table, grant SELECT on the default shared identity tables; restricted tables are refused
    • bff: the default session cookie is __Host-sf_session (sf_session when insecure), NewHandler refuses invalid __Host- and __Secure- cookie configs, and CookieConfig.Domain is removed
    • bff: NewOmniStorageStore with the redis backend requires SiteID and a Sealer (or InsecurePlaintext), NewOmniStorageStoreWithKVS returns an error and requires both, and the default key prefix is session:<SiteID>:
    • bff: NewEntStore requires a Sealer or EncryptionKey (ErrSealerRequired) and writes sealed fields in a format earlier versions cannot open
    • oauthclient: the state cookie is __Host-sf_oauth_client_state; SetStateCookie returns an error, NewStateManagerInsecure takes a *slog.Logger, a StateManager is Secure unless AllowInsecure is set, and SameSite Strict or None is refused
    • organization, approle, resourcegrant, managedprincipal, principal: a revocation whose graph removal fails returns the error and leaves the database unchanged, also in SyncModeEventual; approle.RemoveForMember removes nothing on a graph error, and resourcegrant.GrantInTx may write to the graph before commit when lowering a grant
    • principal: Deactivate fails, and the principal stays active, when the graph refuses to remove its relationships; Update with Active false records a deactivation access change
    • organization: demoting a member to collaborator deletes their application roles in the organization, and admins can add members directly only when APIConfig.DirectAdd allows it
    • authz/mode: in mode rebac the reconciler removes the relationships of deactivated principals and collaborators' application-role relationships
    • scim/store: DeleteUser answers 409 for a user who actively manages other accounts; platform CreateGroup refuses an externalId that is not a valid, available slug, and DeleteGroup soft-deletes and refuses personal organizations
    • contract: RecordAuditEvent, GetAuditStreamConfig and IsAuditStreamEnabled are methods of *contract.API (AuditStreamConfig for the second)
    • systemauth: the connections setting allow_private_egress is removed; use egress_allow_prefixes and allow_http_egress (506c9ed)
    • bff: a redis backend whose RedisURL names a non-loopback server without rediss://, a password or certificate verification fails with an error wrapping omnistorage-core's ErrInsecureConnection unless AllowInsecureRedis is set (ca5266c)
    • keys: an existing connections keyring refuses to open after the upgrade until it is accepted once with systemauth keys accept-rollback --confirm, since keyforge v0.2.0 authenticates the keyring's rollback state; a keyring moved to a new host without that state needs the same (89719ae)

    Upgrade Guide¶

    • Build with Go 1.26.10 or later
    • systemauth: run migrations/0010_oauth_app_allow_bearer_tokens.sql on an existing database; clients must send DPoP proofs, or set allow_bearer_tokens on clients that cannot yet. Several instances share dpop.replay_cache_redis_url; behind a proxy that strips a prefix set dpop.resource_base_url
    • relyingparty: set Config.DPoPKey (shared by instances that share sessions) and BearerConfig.DPoP with a replay cache, or AllowBearerTokens for legacy clients
    • session/middleware: pass a DPoPConfig to HTTPAuth and handle its error, or switch to HTTPAuthBearer to keep accepting only bearer tokens; give APIKeyMiddleware an OwnerCheck
    • session/jwt: set Config.Issuer and an HMAC secret of at least 32, 48 or 64 bytes for HS256, HS384 or HS512
    • multiapp: handle the error from AuthMiddleware and set MiddlewareConfig.JWTService and DPoP.ReplayCache, or DPoP.AllowBearer
    • multiapp: provision a login per app with RoleProvisioning or multiappdb, set AppDatabases and MigrationRole, and run multiapp.Migrate with the owner login as a separate step; for local development set AllowSharedDatabaseLogin or AllowInProcessMigrations
    • bff: give the omnistorage store a SiteID and a Sealer, give the Ent store a Sealer or keep EncryptionKey, and drop CookieConfig.Domain; users sign in again when the cookie name, prefix or sealing changes
    • oauth: configure Config.PrivateKey and choose WithAcceptedClientIDs or WithAnyClient
    • systemauth: pass an AccessChangeScope to WithAccessChanges (AllOrganizations for one application), and make custom session providers return principal IDs
    • organization: allow governed principals through APIConfig.DirectAdd; reassign application roles after promoting a collaborator
    • scim/store: set Config.Syncer to the deployment's syncer
    • multiapp: to keep an app login without the shared identity tables, set SharedReadTables to NoSharedReadTables or pass --no-shared-tables, then apply the provisioning again
    • oauthclient: handle the error from SetStateCookie and pass a logger to NewStateManagerInsecure; flows in progress during the upgrade fail once
    • contract: call the audit stream functions as methods of *contract.API
    • With connections enabled, stop SystemAuth, run systemauth keys accept-rollback --confirm once with the server's configuration, then start it
    • Replace allow_private_egress: true with egress_allow_prefixes listing the ranges local fakes use, for example [127.0.0.0/8], and allow_http_egress: true
    • Point the BFF omnistorage store at rediss:// with a password, or set AllowInsecureRedis for a development Redis on a local network

    Security¶

    • The Go directive was 1.26.6, which misses standard-library security fixes in net/http and HTTP/2, crypto/tls, crypto/x509, html/template, net/textproto and os that are reachable from this module; it is now 1.26.10, so dependent applications build with the fixes
    • SystemAuth issued only bearer tokens, which work for whoever holds a copy, and nothing on the resource side verified the DPoP proofs the BFF sent, so a stolen DPoP-bound token worked as an ordinary bearer token; tokens are now bound to a proven key and every SystemForge resource middleware refuses a bound token presented as Bearer
    • identity/token bound tokens to whatever DPoP thumbprint its caller passed, so a caller that skipped proof verification could bind tokens to a key nobody had proved to hold; it now binds only to a dpopproof.Proof that a Checker verified
    • SystemAuth treated a token subject that was not a UUID or named no principal as active, so the tokens of a hard-deleted principal kept working; such subjects are now inactive and their token family is revoked
    • The embedded auth provider created a session for the oidc method without checking any token, so a caller passing a request-supplied method could sign in as any active user by email; it now verifies only passwords and returns ErrUnsupportedAuthMethod for other methods
    • Password authentication had no attempt limit and returned faster for unknown accounts, allowing unbounded guessing and account enumeration by timing; failures now lock an identifier (ErrAccountLocked) whether or not the account exists, and unknown accounts spend one Argon2id verification
    • A login session created for a managed principal could authorize any client, including ones that never allowed managed principals; /oauth/authorize and the token endpoint now refuse them for such clients
    • POST /login-token did not check where the form came from, so any site could sign a visitor into an account it controlled; the exchange now requires an allowed Origin or Referer
    • Signup created accounts without proof of the address and SignupOrGetExisting handed an existing unverified account to a verified login, letting someone pre-register another person's address; it now returns ErrAccountEmailUnverified
    • UpdateHuman kept the verified flag when callers such as federation sync changed a human's email, so an unproven address linked social logins and was published as email_verified=true; a changed email is now unverified
    • The invite API listed and answered invitations for the caller's email without checking that it was verified, so a principal claiming someone's address could see their invitations across organizations
    • Accepting an invitation did not check that the inviter could still invite, so a removed admin could rejoin through invitations sent to addresses it controlled; acceptance now requires the inviter's current authority, and removing or demoting a member revokes its pending invitations
    • Invite status writes were unconditional, so an accept racing a revoke or decline still created the membership, and revoking an accepted invite left the membership; every transition is now conditional on the invite being pending
    • Under RBAC a deleted organization stayed usable: its slug resolved, its members kept their roles and could add members and accept invitations; deleted organizations now resolve to nothing, give no roles and refuse membership writes (ErrOrganizationDeleted)
    • Any organization admin could add any principal, including another tenant's managed principals, as an active member without consent, and the answers revealed which principal IDs exist; direct adds now need APIConfig.DirectAdd or platform administration and refusals are indistinguishable
    • API key middleware built the principal from a valid key alone, so an organization-scoped key kept working after its owner was removed or deactivated; an owner check now runs on every request
    • identity/oauth API.Middleware accepted any token its storage held, regardless of the issuing client or whether the client or principal was still active; it now requires an accepted, active client and an active principal
    • CreateDelegation let any principal with can_delegate take over any agent, including another organization's or one already delegated; it now returns ErrAlreadyDelegated and ErrCrossOrganization
    • GET /access-changes returned every organization's changes to any client with access_changes:read, and back-channel deliveries went to every client; the feed is now scoped to each client's organizations
    • The contract audit stream state was process-wide, so a token allowed to configure one hosted application's audit stream could repoint or disable another's; the state now belongs to each contract.API
    • The embedded SpiceDB server listened on a local TCP port guarded by a key derived from the startup time, which another local process could guess to write relationships; it now uses an in-memory listener and a random 32-byte key
    • CanAll returned true for an empty action list in the rbac and SpiceDB providers, so a route registered with no actions allowed every authenticated caller; it now denies, and RequireAllActions and RequireAnyAction panic without actions
    • authzguardsql's DefaultResourceBuilder gave every entity and field the same ID-less resource, so a role granted guardsql_field.read could read every field and SpiceDB checks always failed; each entity and field now has a concrete resource ID and organization
    • Targeted feature flags were on for every caller that passed no evaluation context; a flag with targets or a partial rollout is now off without a subject
    • The observability middleware recorded full request URLs and raw paths, sending OAuth codes, API keys in query strings and invite tokens to the tracing backend; spans and metrics now carry the matched route pattern
    • productgraph took the event user from the X-User-ID request header and sent raw request paths, so callers could attribute events to other users; the user comes from the session and paths are recorded as route patterns
    • Marketplace seat assignment read and wrote used_seats outside a transaction, so concurrent assignments overran the seat limit; seats are now reserved with a conditional increment in a transaction
    • Stripe webhooks were verified with an empty key when no signing secret was configured, so a forged checkout event granted a license; verification now fails closed with ErrWebhookSecretRequired
    • Stripe subscription updates were ignored, so unpaid, paused or canceled subscriptions and portal seat reductions left licenses unchanged; licenses now follow the subscription status and quantity
    • The Redis sliding-window rate limiter could count two requests in the same millisecond as one, letting a parallel burst exceed the limit; each entry now has a unique random member
    • The BFF proxy forwarded dot segments, so /api/../../other reached the upstream outside its base path with the session's token; such paths are refused with 400
    • The BFF proxy ignored HeadersToForward and passed client identity headers such as X-User-Id and X-App-ID to upstreams; the list is now enforced and identity, routing and forwarding headers are stripped
    • BFF logout answered success when the session store failed, leaving the session and refresh token valid; it now answers 500 and keeps the cookie so the client can retry
    • BFF sessions were extended by every refresh and never expired from inactivity; sessions now have an idle timeout and a maximum lifetime
    • BFF per-endpoint rate limits shared one bucket per client and never matched under a mount prefix; each endpoint limit now has its own bucket and matches relative to the mount point
    • The BFF session cookie was named sf_session and could be shared across subdomains, letting a sibling subdomain set or overwrite it; it is now __Host-sf_session and always host-only
    • BFF proxy routes skipped the origin check for GET, HEAD and OPTIONS, so a cross-site top-level GET reached the upstream as the user; proxied safe methods are now origin-checked
    • The omnistorage BFF store dropped the site ID on update, logging users out at their first refresh and pushing operators to run without site isolation, and its default key prefix shared the per-user session index between applications; the site ID is kept, required for Redis, and scopes the default prefix
    • The omnistorage BFF store wrote access tokens, refresh tokens and DPoP private keys to Redis in plaintext; they are now sealed with a SessionSealer
    • The Ent BFF store encrypted session fields under one key with no associated data, so ciphertext could be moved between rows or columns and the key could not be rotated; fields are now sealed with key IDs and bound to the session and column
    • The session JWT service accepted HMAC secrets of any length and checked the issuer only when configured; it now requires an issuer and secrets at least as long as the hash output
    • multiapp's Ent hook set search_path at session level, so a pooled connection kept another application's schema, and schema names reached SQL unvalidated; the hook now uses SET LOCAL in a transaction and every schema path validates names
    • The rls migrator and policy SQL interpolated table, column, policy and role names unquoted; they are now quoted as identifiers
    • SCIM filters the store could not evaluate were dropped, so an unsupported filter matched every user and an identity provider could be handed the wrong account; such filters now fail with invalidFilter
    • SCIM PATCH stored a new password in plaintext and PUT never hashed it and echoed it back; both now hash, and no response carries a password or hash
    • SCIM group writes bypassed the organization service, accepting invalid or cooling-off slugs, renaming personal organizations and hard-deleting organizations without graph cleanup; they now go through the organization service
    • SCIM returned database and internal error text to clients; unexpected errors are logged and answered with a generic 500
    • SCIM bulk payload limits were advertised but not applied and every operation could run a bcrypt hash; the payload limit is enforced and password operations per request are capped
    • Deactivating a principal, demoting a member to collaborator, deleting a SCIM user and deactivating a human through SystemAuth storage left the principal's relationships in the authorization graph, so under mode rebac the access remained; each now removes them before committing
    • Revocations committed the database change before removing the relationship from the graph, so a failed graph write left access granted with no retry, and a late grant write could undo a concurrent revocation; revocations now remove graph access first and grants re-read the rows under graph locks
    • A file vault pointed at the keys directory kept the root key beside the keyring, so one backup held everything needed to decrypt connection credentials; root keys in or under the keys directory are refused
    • The OAuth client state cookie could be written without Secure or with an unsafe SameSite mode; it is now __Host-sf_oauth_client_state, Secure, HttpOnly and SameSite=Lax by default
    • The token endpoints parsed the request form before installing their 1 MB body limit; the limit now applies before parsing
    • The BFF omnistorage session store's Redis connection is refused for a server that is not on loopback unless it uses TLS with certificate verification and a password, so session IDs and sealed sessions no longer cross the network in clear text by default (ca5266c)
    • Connections' development egress setting lets provider requests reach only the address ranges listed, instead of every non-public address; link-local and cloud metadata addresses are refused even when listed (506c9ed)

    v0.20.0 - 2026-10-23¶

    Highlights¶

    • Access tokens are bound to the application they were issued for: relying parties, the session JWT service, and multi-app routing each refuse tokens minted for another application that shares the signing key
    • SCIM credentials are bound to one organization: a customer's identity provider provisions only its own members and cannot change the identity of users who also belong elsewhere

    Breaking¶

    • session/jwt: Config.Audience is required; NewService returns ErrMissingAudience without it. Client-kind audiences (bff, api, custom) are added in front of the application audience instead of replacing it, and ValidateAccessTokenWithAudience with an empty audience checks Config.Audience instead of skipping the check
    • relyingparty: VerifyAccessToken accepts only tokens issued to Config.ClientID unless AcceptedClientIDs or AccessTokenAudience is set; client-credentials tokens from other clients must be listed
    • multiapp: without AppAudiences, tokens on app routes must carry the app's AppID as an audience
    • authz: RequireResourceAction no longer sets a resource's organization from the caller's token; extractor errors answer 400 for a missing or malformed ID, 403 for ErrResourceNotFound, and 500 otherwise
    • scim/store: the Ent store refuses requests without a provisioning scope. For a tenant, active is the membership's state, creating a user who exists elsewhere links them as a member, deleting a shared user removes only the membership, and groups cannot be created, renamed or deleted
    • connections: creator rights need an Options.Authorizer that implements authz.OrgAuthorizer (the rbac and SpiceDB providers do); with another authorizer, creators are decided by role and grants alone
    • bff: a custom HandlerConfig.SessionIDGenerator must produce IDs that ValidSessionID accepts (URL-safe characters, at most 256)
    • scim/store: SCIM refuses to deprovision an organization owner, restores memberships with the default role, and for a platform credential active deactivates the account through the principal service

    Upgrade Guide¶

    • session/jwt: set Config.Audience to a value naming the application. Access tokens issued before the upgrade are refused and clients refresh; refresh tokens issued without the audience require signing in again
    • relyingparty: list in AcceptedClientIDs every client, including the application's own ClientID, whose tokens the API must accept, such as service clients using client credentials; or set AccessTokenAudience for an API that many clients call with an audience
    • multiapp: mint tokens with jwt.TokenOptions{Audience: []string{appID}}, or set AppAudiences to the audiences your tokens already carry
    • authzguardsql: handle ErrNoAuthorizedEntities from PolicyBuilder.Build by refusing the query (for example with 403)
    • authz: replace WithResourceID with WithResourceLookup on routes whose access depends on the organization role, passing a lookup that returns the resource's owning organization
    • scim: authenticate with CredentialMiddleware and bind each SCIM credential to its organization (Scope{OrganizationID: ...}); give Scope{Platform: true} only to platform operator credentials
    • scim/store: pass the application's organization service (with its authz syncer) as Config.Memberships and its principal service as Config.Principals, so SCIM changes sync the authorization graph

    Security¶

    • Relying-party bearer authentication accepted a SystemAuth access token issued to any other OAuth client, and an ID token, as an access token for the application, taking the organization memberships in its claims; VerifyAccessToken now requires a client_id claim from an accepted client and refuses typed non-access JWTs
    • The session JWT service's default validation (ValidateAccessToken, HTTPAuth, HTTPAuthOptional) accepted tokens for any audience, so applications sharing a signing key accepted each other's access and refresh tokens; tokens must now carry the service's Config.Audience
    • multiapp AuthMiddleware accepted a token minted for one app on every other app unless AppAudiences was set; a token on an app route must now be addressed to that app's ID by default
    • authzguardsql PolicyBuilder.Build turned a principal authorized for no entity into a GuardSQL policy with empty allowlists, which GuardSQL reads as unrestricted, so the least-privileged principals could query every entity and field; it now returns ErrNoAuthorizedEntities
    • authz RequireResourceAction checked a resource named in the request against the caller's role in the organization from their token, so a member of one organization passed resource checks for another organization's resources; the resource's organization now comes only from the extractor
    • The SCIM store had no tenant scoping, so any SCIM credential could read, change, delete and regroup every user and organization on the platform; each request is now bound to the credential's organization, and requests without a scope are refused
    • SCIM could rewrite the login email of a user who also belonged to other organizations, enabling account takeover; a tenant now changes email, name and photo only for users it provisioned that belong to no other organization, and manages only the membership of others
    • Deactivating an organization membership left the member's organization role, application roles and resource grants in the SpiceDB graph, so under the ReBAC authorizer a deactivated admin kept every permission; deactivation now removes them from the graph and reactivation writes them back
    • bff RegisterHumaRoutes registered stub handlers for logout, session and refresh; on a router shared with Huma, as documented, they took precedence over the mounted BFF handler, so logout answered success without ending the session and the stubs skipped the Origin check and rate limiter. It now only documents the routes
    • A connection's creator kept view, use, manage and share rights on it after leaving or being removed from the organization, and could grant themselves back in; creator rights now require current membership of the owning organization
    • BFF logout passed the client's cookie value to the session store's Delete even when no session matched; with the omnistorage kvs store, the value user:<id> deleted a user's session index, so "log out everywhere" and revoke-on-password-change missed that user's sessions. Logout now deletes only a session the store returns, and malformed cookie values are treated as no session
    • aauthrs accepted an agent token from any agent provider for any agent identifier, so a provider controlled by anyone could claim another domain's agents (for example aauth:billing-bot@victim.example); an agent token is now accepted only when the agent's domain is its issuer's host
    • SCIM wrote memberships directly, so suspending, removing or deleting a user skipped the authorization-graph sync, the access-change record that revokes existing tokens, and cleanup of application roles and resource grants; SCIM now changes memberships through the organization service and deactivates accounts through the principal service
    • SCIM could suspend, remove or delete an organization's owner, letting an identity provider lock a customer out of its own organization; it now refuses with 403
    • Re-adding a suspended member through SCIM restored their previous role, possibly owner or admin; a restored membership now gets the default role

    • systemauth: JWT access tokens carry the JOSE typ header at+jwt (RFC 9068)

    • session/jwt: Claims.HasAnyAudience and ErrMissingAudience

    Security¶

    • Marketplace checkout took the purchaser from the request body, so anyone could start a purchase in another principal's name for any organization (7cf758e)
    • Marketplace listing, license, and seat endpoints acted on any IDs a request named; they now check the caller's permissions on the owning organization (bbac538)
    • The organization API listed every organization and let any caller read, change, or delete organizations, change members, and transfer ownership; it now authorizes each operation (08bd206)
    • Invite management needed no permission, and anyone holding an invite link could accept it as any principal; invites are now managed with invite_member and accepted only by the addressee (236c0e9)
    • Invite tokens were stored in plain text, so a leaked table or backup could accept invites; they are stored as SHA-256 hashes (7ccc80e)
    • SpiceDB principal and organization cleanup ignored failures and missed editor and manager relations, leaving access behind while reporting success (22f7b28)
    • Refresh-token rotation was not atomic and its revocation error was discarded, so a refresh token could be used more than once; refreshing near expiry also reset a session to seven days, extending it indefinitely. Rotation is now atomic, a family keeps its first expiry, and reusing a rotated refresh token revokes the family (2a3c8cd)
    • Stripe checkout granted licenses for sessions completed with an unpaid delayed payment, a malformed seat count produced an unlimited seat-based license, and cancelled subscriptions kept their licenses (fa2a57d)
    • Deactivating a principal left its access tokens valid and let its refresh tokens keep issuing new ones for up to the family's absolute lifetime; SystemAuth and identity/token now refuse an inactive principal's tokens wherever they are used or refreshed, and revoke the family (ebe913d)
    • Revoking an agent's delegation gave it unrestricted access, constraints that did not overlap allowed everything, and delegation expiry and action limits were never stored; delegation now fails closed and enforces every constraint (284806d)
    • UpdateHuman granted or revoked platform administration without syncing it, so a revoked administrator stayed one in SpiceDB (5e002b3)
    • SignupWithInvite let anyone holding an invite link join under any email, and SignupOrGetExisting returned an existing account for an unverified email (e6d07df)
    • SystemAuth's default session provider and identity/oauth's authorization endpoint took the user from an X-User-ID request header, so anyone who could reach the endpoint could obtain an authorization code, and tokens, for any user; header identity is now an explicit, gated opt-in and the default authenticates nobody (645c151)
    • identity/oauth granted every requested scope to every client without consent; non-first-party clients now need a consent check (ef7ea3d)
    • SCIM listing and search never asked the authorization hook, so any caller with a token could dump every user and group, and the provider's default hook allowed everything; listings are authorized and the default denies (0e3dd33)
    • The federation identity sync endpoint trusted any well-formed request and acted on its body, letting an unauthenticated caller link to and then deactivate or rewrite any account by email; it and the lookup endpoint now require a FederationAuthenticator and are not registered without one (d57bf0f)
    • Rate limits keyed on client-supplied X-Forwarded-For and X-Real-IP, so a client could evade a limit by rotating the header or poison a victim's; they key on the direct peer, and forwarded headers are believed only from configured trusted proxies, here and in the BFF client IP handling and the API key middleware (3019061)
    • The in-memory rate-limit store grew without bound from attacker-chosen keys, the middleware failed open on storage errors, and the login token endpoint keyed on raw client_id values; the store is bounded, the middleware fails closed, and only registered clients get a bucket (3019061)
    • Token introspection accepted any valid access token or any client's Basic credentials, public clients included, as the caller's credential; it now requires a confidential client or a token with the introspect scope (5e6dba0)
    • The default storage accepted every client-assertion JWT ID as new, so a captured private_key_jwt assertion could be replayed until it expired (2ae4f56)
    • BFF cookies lost Secure and HttpOnly when a CookieConfig omitted them; both are now unconditional unless AllowInsecure is set for development (d1d897c)
    • Cookie-authenticated writes through relyingparty.BearerMiddleware skipped the same-origin check, allowing cross-site requests (ebf1095)
    • JWT validation accepted tokens with no expiry and ignored the issuer; the contract middleware did the same and skipped the audience check without an app ID (7061c67)
    • Client secret validation revealed whether a client ID existed by error message and timing, and lockout counted differently spelled identifiers separately, restarting the count (30bd958)
    • multiapp's SchemaDB left a schema's search_path on pooled connections, which could carry one application's schema to unrelated code, and ForSchema interpolated unvalidated names into SQL (012e2db)
    • The BFF proxy forwarded the browser's session cookie upstream when a ProxyConfig was built by hand; Cookie, Authorization, and DPoP headers are now always stripped (3c54fc2)
    • multiapp trusted the X-App-ID header, so with a shared signing key a token for one app authenticated requests for another; MiddlewareConfig.AppAudiences binds tokens to the routed app (73e0d19)
    • API keys could be read, revoked, or deleted by ID alone, requested any scope including the wildcard when no allow-list was set, and ignored MaxKeysPerUser (0a3cf11)
    • Lockout let a burst of parallel guesses exceed MaxAttempts; Lockout.Begin reserves the attempt before the credential is verified (43c3818)
    • Concurrent BFF refreshes spent one refresh token several times, which token reuse detection treats as theft; refresh is now serialized per session (a77d8df)
